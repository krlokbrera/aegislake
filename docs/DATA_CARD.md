# Data card

## Default simulator

The default dataset is generated by original project code with a fixed random seed. It includes routine access, stale passwords, service batches, password spraying, broad resource access and subtle authorized-looking malicious access.

There are no real people, live IP addresses, employer records, credentials or client logs in the generator. Labels reflect injected scenarios. Good simulator performance does not establish performance against real attackers.

Benign and malicious behavior intentionally overlap. Daily stealth access can be indistinguishable from normal activity under the current features. Perfect recall is not an acceptance criterion.

## Canonical event contract

| Field | Type | Meaning |
| --- | --- | --- |
| event_id | nonempty bounded string | Stable source event identity |
| timestamp | ISO 8601 text with timezone | Event time, normalized to UTC |
| user | nonempty bounded string | Identity or pseudonym |
| source | nonempty bounded string | Source host or pseudonym |
| destination | nonempty bounded string | Target resource or pseudonym |
| success | JSON boolean | Observed authentication outcome |
| mfa | boolean or null | Observed MFA evidence; null means unknown |
| country | nonempty bounded string | Country code or unknown marker |
| label | 0, 1 or null | Ground truth, never a predictor |
| scenario | bounded string | Synthetic provenance; never a predictor |

Unknown fields are rejected. Required identifiers have a 200-character maximum. Labels represented as booleans are rejected even though Python otherwise treats bool as an int subtype.

The contract is project-specific; it is not certified compliance with OCSF, ECS or an Azure product schema.

## Example

```json
{
  "event_id": "syn-000000001",
  "timestamp": "2026-01-05T10:02:00+00:00",
  "user": "employee-0001",
  "source": "workstation-0001",
  "destination": "app-02",
  "success": true,
  "mfa": true,
  "country": "ES",
  "label": 0,
  "scenario": "routine"
}
```

## Quality and deduplication

Every input line is accepted, counted as an exact duplicate, or rejected. Conflicting duplicate identifiers retain the first accepted event and quarantine the later record. The simulator intentionally adds one exact duplicate and one malformed record.

An empty valid dataset fails the run. Malformed UTF-8 is a file-level error. The implementation does not impose a maximum input line byte length; deploy only on trusted bounded-size exports until an ingestion size limit is added.

## Microsoft Entra export adapter

The local adapter supports the documented Graph sign-in shape, using `id`, `createdDateTime`, `userId`, `ipAddress`, `resourceId` or `appId`, status, country and authentication step details. It does not fetch pages, follow `@odata.nextLink`, or obtain API credentials.

Keep the raw export outside the repository. HMAC pseudonyms require a private key, a stable namespace and consistent key handling across batches. Rotate deliberately: changing the key changes the identity join space. Country and timestamps can still be sensitive in combination with external information.

MFA policy requirements are not completion evidence. Missing step details become null. Source-provided risk labels such as `riskState` are deliberately excluded to avoid treating an existing detector as ground truth.

## Real dataset research

LANL's public multi-source dataset is a possible external benchmark, with authentication records and a small red-team event list. Its relative epoch, older network environment and incomplete negative ground truth make direct transfer to modern cloud identity detection inappropriate.

The project does not bundle or automatically download LANL data. A bounded ingestion adapter, explicit label-join tests and a documented sampling plan must be added before using it as validation evidence. See the research report and primary citation there.

## Retention and publication

Local bronze, silver and run folders are ignored by Git. The Azure publication command accepts only runs marked as synthetic and sends an allowlist of report files to an existing private container. It does not upload bronze or silver data.

The Bicep lifecycle policy expires synthetic report blobs after 30 days; seven-day soft deletion adds temporary recovery retention. Lifecycle execution is asynchronous. This policy is not a universal retention recommendation for security investigations.

## Dataset limitations

No validated representation of tenants, conditional access policies, endpoint posture, seasonal schedules, compromised service principals, real device trust, incident adjudication, token theft or correlated campaigns is claimed. A real pilot needs its own data owner, lawful access assessment, minimization rules and measurement design.
